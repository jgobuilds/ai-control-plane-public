Lanes (cross-cutting use cases)

Each n8n workflow is a use case that spans scopes.

LaneDescription
Approval gate (reusable)Call via Execute Workflow with { title, message, source, autoApprove? }. Sends an approval request through the channel-abstracted Notify sub-workflow with Approve/Reject links, then WAITS until a link is clicked. Returns { approved, auto, timedOut }. Timeout (24h) = rejected — default deny. autoApprove:true short-circuits to approved (lets callers keep one linear flow and decide per-scope whether a human is required).
Ask a human (agent question gate)The question gate: pages a human, serves a form, and blocks until they answer or the timeout expires. Returns `answered` separately from `answer`, so "nobody replied" can never be mistaken for an empty answer.
Ask a human (HTTP door for the runner)HTTP door for a runner to raise a question mid-run. Responds immediately, starts a Slack thread watch alongside the form, and hands the answer back through the router rather than straight to a runner.
Daily digest lane (scheduled, human-awareness digest tier)Density-adaptive daily digest — the 'stay aware' tier between interrupt (CI alerts) and on-demand (the ledger). A Schedule Trigger calls the `lanes` service over the internal network (GET lanes:8081/digest?days=1, header x-lanes-token from $env.LANES_TOKEN); lanes runs scripts/daily_digest.py — a thin formatter over eval_metrics.py — and returns the FINAL { post, severity, title, message, source } payload, leading with anomalies (drift / blocks / change-failures) and stating coverage before any notional total. n8n cannot run python itself (hardened image, no package manager — see docs/decisions/0006), so the lane runs in `lanes` while the SCHEDULE, EXECUTION LOG, IF gate and Notify seam all stay in n8n. A Code node parses the response (and synthesizes an error post if the call failed, so the lane never goes dark), then the IF gate calls Notify ONLY when post===true — ordinary quiet days stay silent and a single weekly heartbeat (default Monday) proves the lane is alive. Ships INACTIVE. Deploy with `python scripts/n8n_bootstrap.py --import daily-digest.workflow.json` then `--dry-run brightworks-daily-digest`, then `--activate brightworks-daily-digest` — no UI clicks. Channel is chosen at the Notify seam (NOTIFY_CHANNEL / SLACK_WEBHOOK_URL). Metadata only; the ledger carries no prompts or PII. See ai-standards/references/notification-taxonomy.md and AIOPS.md.
Deliverables → Drive (rehydrated)Outbound half of the sync loop, with a human gate. Picks up tokenized deliverables agents wrote to workspace/scopes/<chain>/deliverables/, rehydrates PII via the scrubber vault (post-model), requests approval (skippable per scope via REQUIRE_APPROVAL), uploads to the scope's Drive folder, then acks so originals archive to deliverables/sent/. Attach your Google Drive OAuth2 credential to the Upload node; set the approval-gate workflow ID in the Request approval node.
Dependency bumps (scheduled lane, AG-3)Weekly closed-loop maintenance lane: fans out dependency work into isolated worktrees, each self-verifying, then notifies with merge-ready branches. No approval gate before the run — nothing irreversible happens; the human gate IS the merge (branches never auto-merge). Set repo/base/verify in the Config node and the Notify workflow ID in the Notify node.
dispatchWork-dispatch lane (ADR 0012). Every 10 minutes it asks the `lanes` service to claim ONE ready ticket (GET lanes:8081/dispatch?assignee=…), then hands the resulting payload to the ROUTER. It never calls a runner: the router is the only path to one, and a second path is the open C2 threat-model finding. SINGLE WRITER — do not run a second copy of this lane against the same ticket store; that is what makes the claim safe without a lease (ADR 0010 N2). An empty queue is the normal state and ends the run quietly; a BLOCKED ticket (no acceptance criterion, or hop ceiling reached) notifies a human, because those need judgement rather than another agent. BACKEND: defaults to `file` because the lanes container has no `gh` binary and no GitHub credential — reaching GitHub Issues from here needs either gh in the image or a token plus an API transport, and putting a credential in this service is an exposure decision rather than a code change. Set TICKET_BACKEND=github once that is decided; the seam is why it is a one-word change.
Drive → workspace sync (scrubbed)Pulls changed files from a scope's Google Drive folder, runs them through the PII scrubber, and lands tokenized text in workspace/scopes/<chain>/ingest/. Attach your Google Drive OAuth2 credential to the two HTTP nodes. Set FOLDER_ID + scope in the Config node. Activate for the schedule + last-sync memory to work.
Global Error HandlerSet this as the Error Workflow on your other workflows (Workflow Settings -> Error Workflow). Captures failure context and routes it through the channel-abstracted Notify sub-workflow. Kept intentionally minimal: a complex error handler fails itself.
Eval / drift lane (scheduled, AG-3)Weekly continuous-eval lane. A Schedule Trigger calls the `lanes` service (GET lanes:8081/eval-metrics?days=7, header x-lanes-token from $env.LANES_TOKEN), which runs scripts/eval_metrics.py over the audit ledger and returns analyze() as JSON. n8n cannot run python itself (hardened image — see docs/decisions/0006), so the lane runs in `lanes` while the SCHEDULE, EXECUTION LOG and Notify seam stay in n8n. A Code node formats agentic-leverage + quality metrics and any drift WARNs into { severity, title, message, source }; severity is 'warn' if any drift flag OR the ledger hash chain fails to verify OR the lane call fails. This measures metadata the router already logs; it is NOT a semantic eval — see docs/design/EVAL.md. Deploy with scripts/n8n_bootstrap.py — no UI clicks.
Feedback → eval inbox (thumbs-down capture, SCAFFOLD)Closes the agent improvement loop from a human thumbs-down to a captured regression case WITHOUT needing python inside n8n. A Webhook (or Manual) trigger receives { scope, prompt, output, verdict, note }; a Code node shapes it into a case record; a Write-file node drops it to eval/inbox/<id>.json. A human/operator then runs `python scripts/eval_capture.py --dataset <name> --ingest eval/inbox --scrubber-url ... --scrubber-token ...` to TOKENIZE the prompt and promote it into eval/datasets/<name>/, and `python scripts/eval_run.py` to gate. Ships INACTIVE. REQUIRES ./eval mounted into the n8n container (e.g. volume ./eval:/data/eval) so the Write node can reach eval/inbox. The raw prompt is only tokenized at the eval_capture step — if this webhook may receive raw client PII, terminate it inside the trusted network and treat eval/inbox as sensitive (it is .gitignored). See IMPROVEMENT-LOOP.md + EVAL.md.
Incident responder (event-driven skills, AG-3)Source-agnostic incident lane: a webhook accepts PagerDuty, Alertmanager, Slack slash-command, or generic payloads; the agent diagnoses using the scope's skills; a human approves before any fix is applied (via the AG-2 worktree fan-out, merge stays human); the learning is encoded back into a skill. Set the approval-gate workflow ID and tokens; see README.
Notify (channel-abstracted)Reusable notifier. Call via Execute Workflow with { severity, title, message, source }. Routes to Slack / Teams / Email / generic webhook based on the NOTIFY_CHANNEL env var, so callers never hardcode a channel.
Parallel worktree fan-out (AG-2)Fans several agents out in parallel, each isolated in its own git worktree, each self-verifying. Calls claude-runner /fanout. Nothing is merged or pushed — you review branches agent/<id> (or patches in workspace/.fanout) and merge by hand. Requires a git repo at workspace/<repo>.
Promote skill (scrub → review → commit)The only sanctioned path for knowledge to move UP the scope tree. Previews the scrubbed skill, sends it through the approval gate (never auto-approved), and commits to the target scope only on explicit approval. The scrubber refuses non-ancestor targets and re-checks for raw PII at commit. Set scope/file/toScope in the Config node and the approval-gate workflow ID in the Request approval node.
Research watch (scheduled)Weekly watch over the six projects tied to a recorded decision. Fetches in `lanes` (the runners are firewalled), asks an agent which decisions actually move, and skips the model call entirely on a quiet week.
Retention sweep (scheduled lane)Retention visibility lane — DRY-RUN ONLY. A Schedule Trigger calls the `lanes` service (GET lanes:8081/retention, header x-lanes-token), which runs scripts/retention_sweep.py WITHOUT --apply and returns the report. The endpoint has no apply parameter at all, so this lane cannot delete a file or prune the vault however it is called — enforced as a capability, not a setting. The PII token vault is deliberately NOT mounted into `lanes` (the vault never leaves the scrubber), so vault pruning is NOT inspected and the message says so; the raw report's '0 vault entries prunable' line must not be read as a finding. Actually enforcing retention stays a human-invoked action on the host. n8n keeps the schedule, execution log and Notify seam — see docs/decisions/0006. Deploy with scripts/n8n_bootstrap.py.
Cost-tiered dispatch exampleCalls the cost-tiering router instead of a runner directly. The router applies deterministic rules, picks the cheapest capable model, and can cross-verify. Set task_type to steer the tier, or omit it to let the router triage.
