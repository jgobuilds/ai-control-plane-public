# AI Control Plane

A multi-agent orchestration framework: work enters through one router, disperses
into cost tiers and isolated lanes, and ships only through verified, human-gated
exits. n8n handles triggers and glue; a cost-tiering router dispatches to
firewalled runners that shell out to vendor CLIs, so model calls bill against
whatever entitlement the operator already holds.

**That entitlement is capped, and smaller than it looks.** On Anthropic, `claude -p`
has drawn on a per-user monthly Agent SDK credit rather than plan usage limits
since 2026-06-15 — $20/$100/$200 by plan, metered at standard API rates, and
requests **stop** at the ceiling unless usage credits are enabled. Read
[`docs/design/PROVIDER-BILLING.md`](docs/design/PROVIDER-BILLING.md) before
planning capacity; it carries the quoted primary source and the per-vendor
detail. The design does not depend on the answer — the router chooses the tier,
so a terms change moves cost, not architecture — but the cost is real and
bounded, so do not describe it as free.

## The rule that shapes every change

**This repo ships brand-neutral.** Real org identity — palettes, org names,
marketing pages — lives in a private overlay resolved generically at
`../<org>-instance` (or `$AICP_INSTANCE`), never here. The pre-commit guard
enforces it:

```bash
python scripts/check_public_hygiene.py            # staged files — the commit gate
python scripts/check_public_hygiene.py --tree     # every tracked file — the CI gate
```

Both modes matter. Staged-only scans nothing in CI, where nothing is ever
staged — it would pass while checking nothing.

## Do not hand-edit generated files

| File | Generated by |
|---|---|
| `docs/design/ARCHITECTURE.md`, `docs/design/architecture.html` | `scripts/gen_architecture.py` |
| `docs/compliance-map.md` | `scripts/gen_compliance_map.py` |
| `docs/usecase-register.md`, `usecase-register.html` | `scripts/gen_usecase_register.py` |
| `docker-compose.yml` (scoped variants) | `scripts/gen_compose.py` |

Edit the source and regenerate. A hand-edit here is silently overwritten.

**Adding a context file needs the same regenerate.** Runner mounts are computed
from what exists on disk when `gen_compose.py` runs, so a `CLAUDE.md`, `skills/`
or `glossary.md` added to a scope afterwards is invisible to the agent — no
mount, no error, just worse output. Regenerating is not enough either; the
container has to be recreated. Both gaps are caught by:

```bash
python scripts/mount_drift_check.py --live
```

`--live` reads the paths inside the running containers, because "generated" and
"deployed" are separate claims and only the second one is what the agent sees.

## Real scope content lives in the overlay

`workspace/` is tracked and ships in the public snapshot, so real scope subtrees
are gitignored here (allowlist: only the sample tree is tracked). The
authoritative copy of real context lives in `<overlay>/workspace/`, and the
engine's tree is a **deployment artifact — do not edit it in place**:

```bash
python scripts/sync_workspace.py            # overlay -> engine, refuses over local edits
python scripts/sync_workspace.py --check    # report drift, change nothing
python scripts/harvest_workspace.py         # engine -> overlay: what did agents write?
python scripts/harvest_workspace.py --apply # copy it back (never commits)
```

**Agents write too.** A real run produced an n8n workflow under `internal/`, which
lived only in the engine's gitignored `workspace/` — versioned nowhere, one
rebuild from gone. `harvest_workspace.py` is the return path, and it is a review
step rather than a sync: it reports by default, skips anything the engine already
tracks, refuses when both sides moved, and never commits. Read agent output before
you keep it.

The full sequence after changing overlay context is sync → `gen_compose.py` →
recreate the containers → `mount_drift_check.py --live`. The sync keeps a
manifest of what it wrote so it can refuse to overwrite an edit it did not make;
that refusal is the feature, and `--force` is how you overrule it.

## Design constraints

- **Deterministic before models.** The router tries rules first, then the
  cheapest capable tier. Don't reach for a model where a rule will do.
- **Human gates on irreversible acts** — merges, shipping, promotions,
  deletions. The gate is the product; removing one is a design change, not a
  refactor.
- **Every decision is appended to the audit ledger.** Don't add a path that
  acts without writing a record.
- **Only the router may reach a runner.** Tiering, the ledger, the kill switch,
  PII policy and cross-vendor blocking all live there, so a direct call gets the
  agent and none of them. Route through `http://router:8080/route`.
  `python scripts/boundary_check.py` enforces it across the whole tree — it is
  not an import rule, so no architecture-conformance tool can see it.
- **Runners are firewalled and talk only to their vendor.** The scrubber's PII
  vault is never mounted into a runner.
- Autonomy follows verification — see [`docs/design/LADDER.md`](docs/design/LADDER.md)
  for the rung-by-rung intent.

## Pins move by policy, and deploys go one runner first

Every third-party image and agent CLI is pinned. Version updates wait 7 days
(security fixes do not), an eligible upgrade must be taken within 30, and a new
Claude Code version is not promoted until `scripts/probe_cli_enforcement.py`
exits 0 against it. Ship with `scripts/rollout.py` from the live checkout —
canary, observe, promote — not a bare `docker compose up -d --build`, which
recreates everything at once. Full process: [`docs/runbooks/UPGRADES.md`](docs/runbooks/UPGRADES.md).

## A failure that happens twice is a harness bug

Fix the first one and move on. On the **second** occurrence of the same
signature, the fix belongs in the harness, and
[`reliability/recurrence.yaml`](reliability/recurrence.yaml) has to say what was
done — with a command that proves it, or a dated `until` if you are knowingly
carrying it:

```bash
python scripts/recurrence.py report        # what is recurring here
python scripts/recurrence.py check         # the gate
```

CI runs `check --shape` (occurrence counts live in gitignored `audit/`, so a
counting gate there would check nothing). Full rationale in
[`docs/design/RECURRENCE.md`](docs/design/RECURRENCE.md).

## Research: quote it or do not claim it

`WebFetch` answers a prompt about a page using a small fast model, so what
reaches the agent is that model's answer, not the page. Handing the job to a
subagent does not fix it — a subagent returns prose too. Fetch to a **file** and
quote from it:

```bash
python scripts/fetch_source.py get <url> [--name slug]   # raw text -> research/raw/
python scripts/fetch_source.py quote <slug> <regex>      # line numbers you can cite
```

Three rules, all learned the hard way on
[`PROVIDER-BILLING.md`](docs/design/PROVIDER-BILLING.md):

- **Every load-bearing claim carries a quotable line** — slug, line number, and
  the date the page was read. Checking a claim should be a grep, not a judgement.
- **Prefer the primary source, and date it.** That file's worst error was not a
  mangled summary: three blogs said a billing change had been cancelled, the
  summarizer relayed them faithfully, and the vendor's own page — a day newer —
  said it had taken effect. Blogs agreeing with each other are one source.
- **"Could not confirm" is a finding.** Write it down rather than smoothing it
  over, and mark the claim's confidence accordingly.

## Decisions get an ADR

Architectural choices go in `docs/decisions/` using
[`TEMPLATE.md`](docs/decisions/TEMPLATE.md), including a **Cost** column in the
options table. `scripts/adr_check.py` enforces the shape.

## Two directories that are not what they look like

Most of the tree explains itself from its names. These two do not:

- **`workspace/`** is a *runtime* context-scope tree bind-mounted into the
  runners — a product feature, not documentation about the repo. Editing it
  changes what agents can see.
- **`context/`** holds the neutral `*.example` fallbacks that the private overlay
  replaces at runtime. The committed values are deliberately not the real ones.

House engineering lenses are wired via `.engineering-standard/config.yml` to
`../ai-standards`. That path resolves on disk only — this file must carry
everything a contributor actually needs.
